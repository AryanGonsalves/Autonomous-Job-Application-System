1. GREENHOUSE — DIRECT COMPANY PORTAL SUPPORT
The existing app already has basic Greenhouse support. Expand it significantly:
New file: scrapers/greenhouse.py (replace or extend existing)

Maintain a seed list of companies that use Greenhouse in scrapers/greenhouse_company_seed_list.json. Populate it with at least 100 well-known tech/data companies (e.g. Stripe, Airbnb, Figma, Notion, Robinhood, Duolingo, Coinbase, Dropbox, Twilio, Asana, etc.).
For each company in the seed list, hit the public Greenhouse API endpoint: GET https://boards-api.greenhouse.io/v1/boards/{company_slug}/jobs?content=true
Parse the JSON response. For each job, filter for:

Title contains any of: "analyst", "data scientist", "analytics", "business intelligence", "BI", "data science"
Location passes the US filter (see Section 3 below)


Store the job's absolute_url — this is the company's own careers page (e.g. https://stripe.com/jobs/listing/12345), NOT the boards.greenhouse.io URL. Always apply via the company's own portal.
When applying: use Playwright to navigate to the absolute_url. Greenhouse forms appear on company sites in two ways — handle both:
Mode A — Standalone Greenhouse page (e.g. stripe.com/jobs/listing/12345 that loads Greenhouse directly):

Detect by presence of greenhouse.io in page scripts or the #application form element in the DOM.
Fill fields directly on the page: first name, last name, email, phone, resume upload (set_input_files()), cover letter textarea or upload, LinkedIn URL, website/portfolio, location, custom questions.

Mode B — Embedded Greenhouse iframe on a company's own careers site (e.g. notion.so/careers with a Greenhouse form embedded as an <iframe src="https://boards.greenhouse.io/embed/job_app?..."> or a JS-injected widget):

Detect by checking for an <iframe> whose src contains greenhouse.io or boards.greenhouse.io/embed, OR a <div id="grnhse_app"> element (Greenhouse's standard embed container).
Switch the Playwright frame context to the iframe using frame = page.frame_locator('iframe[src*="greenhouse.io"]') before interacting with form fields.
Fill all the same fields as Mode A but scoped inside the iframe frame context.
If the embed loads via JavaScript (no iframe src present initially), wait for #grnhse_app to populate before proceeding.

For both modes, after filling all fields, click the Submit button and wait for a confirmation element (e.g. "Application submitted" text or a thank-you URL) before marking the job as applied.
Any custom questions in either mode: pass to ai/ats_answers.py to generate a short contextual answer.
Make the greenhouse_company_seed_list.json editable from the Settings page in the dashboard (add/remove companies via UI).

3. US-ONLY LOCATION FILTERING
Add two layers of filtering to ensure only US-based jobs are applied to. Do this across ALL platforms.
Layer 1 — Search-level parameters (update each existing scraper):

LinkedIn: set geoId=103644278 (United States) in the search URL parameters.
Indeed: set l=United+States in the search URL. Also accept remotejobs=1 as a secondary search.
Handshake: set location filter to "United States" in the search UI via Playwright.
Greenhouse API: filter by location field in the API response JSON.
Lever: filter by location field in the API response JSON.

Layer 2 — Post-scrape validation (add to engine/queue_manager.py):
Create a utility function is_us_location(location: str) -> bool:

Returns True if the location string contains any of:

A US state name (Alabama, Alaska, ... Wyoming) or 2-letter abbreviation (AL, AK, ... WY)
"United States", "USA", ", US", "U.S."
"Remote" — ONLY if no non-US country name is also present in the string


Returns False otherwise.
Maintain a list of common non-US country names to cross-check against for the "Remote" case.

In the queue manager, after scraping and before inserting into the DB queue:

Run every job through is_us_location().
If it returns False, insert the job into the DB with status filtered_non_us (do not add to the application queue).
Add a country_resolved column to the jobs table to store the detected country result.
Show a "Filtered (non-US)" count on the dashboard home stats panel so the user can see how many were excluded each run.

Settings page: Change the location preference field label to "Location (US only — optionally narrow to a city or state)" with a note that the country is always locked to the United States.

4. SCHEDULER — TIMER & DAILY AUTOMATION
Upgrade the existing scheduler to support full daily automation with a visible timer.
Backend changes (scheduler.py):

Use APScheduler with AsyncIOScheduler and a SQLAlchemyJobStore pointed at the existing SQLite DB so scheduled jobs persist across app restarts.
On app startup, read the schedule config from the settings table and re-register all active jobs automatically — no manual re-setup after a restart.
Support up to 3 configurable daily run time slots (e.g. 8 AM, 1 PM, 6 PM). Store each as a cron expression in settings (scheduler_slot_1, scheduler_slot_2, scheduler_slot_3).
If multiple slots are configured, divide the daily_cap evenly across them so the total never exceeds the user's limit.
Expose these API endpoints (add to main.py):

GET /api/scheduler/status — returns: enabled (bool), next_run (ISO timestamp), slots (list), current_run_active (bool)
POST /api/scheduler/update — update slots and enabled toggle
POST /api/scheduler/run-now — trigger immediate pipeline run
POST /api/scheduler/stop — gracefully stop the current run after the active application finishes



Frontend changes (dashboard Scheduler panel):

Add a live countdown timer showing "Next run in: HH:MM:SS" — update every second via setInterval polling /api/scheduler/status.
Add an enable/disable toggle switch.
Add up to 3 time picker inputs for daily run slots.
Add a "Run Now" button and a "Stop Current Run" button (the stop button should only be active while a run is in progress).
Add a Run History table showing the last 30 runs: timestamp, platform breakdown, jobs scraped, jobs applied, jobs failed, duration.
Store run history in a new run_history table in the DB:

  run_history
    id, started_at, finished_at, jobs_scraped, jobs_applied, jobs_failed,
    jobs_filtered_non_us, triggered_by (scheduled/manual)
